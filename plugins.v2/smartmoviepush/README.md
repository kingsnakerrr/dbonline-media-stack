# 智能下载影视资源_惹咪之北

> 0.9.68：等候队列每轮只按一个片名搜索馒头，重试时轮换原名、英文名、中文名，让有限的站点额度覆盖更多年度候选；连续 3 次真实无资源仍移入独立列表，站点限额和故障不计次。

MoviePilot V2 私人电影推荐与下载插件。插件从 TMDB 候选中排除媒体库已有影片，再到所选 PT 站点搜索资源，按 MoviePilot 过滤规则选择结果，可推送到 Telegram 或自动提交下载。

## 主要功能

- 定时 30、60、120、180、240 或 300 分钟运行
- 自动下载与手动确认两种模式
- 限制同时下载任务数，超出后进入顺序等候队列
- 随机与年度候选独立占用下载名额，交替获得站点搜索机会；一部影片失败不会卡住同来源的后续候选
- 无资源电影独立展示，可单个、勾选批量或按分类全部重查；重新发现资源后返回等候队列
- 硬盘剩余空间保护，空间不足时暂停定时与手动推荐、停止新增下载；旧下载和既有等候队列保留
- 等候下载、不再推送列表支持搜索和分页；首页“下载记录”卡片是唯一入口，点开默认显示全部，可切换今天、昨天、本周、本月、上个月、今年或指定提交日期（含 SQLite 归档），搜索影片或 TMDB ID，按状态查看，默认每页 100 条并可翻页
- Telegram 推荐、下载按钮、不再推送按钮及每日统计
- Telegram 管理员首次打开独立机器人时点 Open 即可由 `/start` 打开菜单；`/smartmovie` 查看统计，`/smartcontrol` 打开随机定时推送、随机自动下载和年度下载的独立启停按钮，`/smartstatus` 查看队列和下载状态，`/smartdisk` 查看检测盘的容量、已用、剩余和保护阈值，`/help` 查看用法。共享 MoviePilot 机器人也注册了带 `smart` 前缀的命令。暂停只阻止新增自动下载，不中断 qB 已开始的任务；随机手动确认仍可提交。只有配置的 Telegram 管理员可使用这些命令和按钮。统计按任务提交时间归属周期，保留记录不足时会提示可能不完整。
- 插件下载记录超过近期 1000 条时，较旧任务会自动写入插件数据目录的 SQLite 归档；后台继续核验并写回归档任务的下载、整理和 Emby 状态，周、月、年统计会合并查询。升级前已被旧版本截断的记录无法凭空恢复，统计会标出可核验记录起点。
- 每日统计每行一部电影，尽量合并为单条 Telegram 消息；已入库影片不加后缀，🟠 表示未完成下载，🟡 表示下载完待整理，🔴 表示整理失败或待入库，超过单条容量才拆分。
- 每 5 分钟核对下载器完成状态，并查询已连接且启用的 Emby；只有 Emby 当前确实查到电影才标记已入库
- 每天 00:00 以上一自然日本插件提交的任务为总账，按种子 hash 核对 qB 下载完成、MoviePilot 整理成功/失败和 Emby 是否已有；每项标出当前阶段，失败名单单独发送。Emby 暂不可用时暂缓发送并重试，避免低报。同一电影提交两次按两项任务计数。
- 点击“立即运行”后可在页面查看当前阶段、查询数、选中数和已推送数；“查看日志”默认只看推送/下载记录，开启“详情日志”可查看手动操作、定时任务、TMDB 候选、逐部站点查询、过滤或跳过原因、发送结果及错误。已在运行时再次点击会记录跳过原因，不会并发启动第二轮。
- 每轮优先复用 Emby 完整电影索引批量排除已入库候选，索引不可用则回退 MoviePilot 逐部检查；正在同步中的 MP 媒体表不会被当成完整片库。新上映尚难找到资源及近期反复搜空的候选会适度后排，不硬性排除；无资源缓存按上映时间调整重试间隔，并在站点或过滤规则变化时失效。
- “按年份筛选电影”一次扫描所选年份的 12 个月，保存完整 TMDB 候选名单；“高口碑”按最低评分和评价人数筛选，“主流”补充有一定评价人数但评分未达门槛的热门电影。名单默认按评价人数排序，可按分类、上映月份与状态过滤；打开名单不会查询 PT。已有按月名单保留在折叠的旧记录中。
- 年度名单可全选当前页或逐部选择。点击“加入年度候选”后先核对 Emby、MoviePilot 下载状态及共享等候队列，未重复的影片只登记为年度候选，不立即下载。首页可设置年度同时下载上限和每分钟最多新增数量；点击“启动推送下载”会立即尝试补位，随后每分钟检查空位，也可暂停。年度候选与随机候选各用自己的并发名额；有年度空位时才按相同的站点搜索与 MoviePilot 过滤规则选择资源。连续 3 次没有匹配资源的候选转入“无资源”列表，不会伪装成已下载；旧的 PT 预查缓存不再决定年度名单的资源状态。
- “创建并扫描”只建立候选名单，不自动下载；旧版年度任务的自动搜索入口已停用。TMDB 扫描失败时会显示年份、月份、日期窗口和页码，方便定位参数错误。
- 年度名单、随机／定时任务、Telegram 手动确认与队列补位共用 TMDB ID 去重：任一路径真正提交下载成功后会移除同片等候任务；提交失败不会误删队列。
- 插件下载记录弹窗显示下载完成时间和整理/入库状态，按“Emby 已入库、待入库、未下载完成、已整理、整理失败、已整理未入库”分栏；MP 已整理但 Emby 24 小时内未找到显示“已整理”，超过 24 小时仍未找到进入最后的“已整理未入库”排查栏。这只能提示需检查上传、扫描或匹配，不能单凭状态认定 rclone 上传失败。有明确整理失败记录时可在该行悬停查看错误。
- 入库数量只根据已连接 Emby 的实际影片索引核实，不直接读取或修改 Emby 的内部数据库。
- qB 保留的任务按下载器原始完成时间确认；已经删除的旧种子只能由 MoviePilot 成功整理记录反证完成，历史完成时间以整理时间兜底。日报归属日期由插件任务的提交时间决定，而不是 qB 完成日期。
- 私人固定密码保护；密码只保存为加盐哈希

## 手动安装

适用于 Docker 版 MoviePilot V2。以下示例假设容器名为 `moviepilot-v2`，配置目录为 `/opt/docker-compose/moviepilot/config`。

1. 解压安装包，确认得到 `smartmoviepush` 文件夹。
2. 将整个文件夹复制到 MoviePilot 的本地插件目录：

   ```bash
   mkdir -p /opt/docker-compose/moviepilot/config/local-plugins/plugins.v2
   cp -a smartmoviepush /opt/docker-compose/moviepilot/config/local-plugins/plugins.v2/
   ```

3. 确认容器实际加载的文件也已更新。当前 `takehost` 部署必须同时复制进容器；只更新宿主机目录不会让页面生效：

   ```bash
   docker exec moviepilot-v2 mkdir -p /app/app/plugins/smartmoviepush
   docker cp smartmoviepush/. moviepilot-v2:/app/app/plugins/smartmoviepush/
   ```

4. 重启 MoviePilot，并核对容器内的 `plugin_version` 与安装包版本一致：

   ```bash
   docker restart moviepilot-v2
   docker exec moviepilot-v2 grep plugin_version /app/app/plugins/smartmoviepush/__init__.py
   ```

5. 打开 MoviePilot 的“插件”，进入“智能下载影视资源_惹咪之北”。

## 基本使用

1. 打开“插件状态”。关闭后不会定时推荐、提交排队任务或执行空间保护。
2. 选择定时推送间隔和“自动下载/手动下载”。
3. 设置每轮数量、立即运行数量（均为 1–50 部）、同时下载上限、TMDB 最低评分和资源搜索站点。不合法的输入会提示错误，不会悄悄改回旧值。
4. Telegram 三个输入框留空时跟随 MoviePilot 的 Telegram 通知配置；只需填写要覆盖的项目。
5. 设置硬盘保护检测路径、停止新增阈值和恢复阈值。
6. 保存设置后可点击“立即运行”测试真实搜索与下载流程。

“立即运行”不受定时推送开关影响，但仍遵守同时下载上限和硬盘保护。硬盘保护启动时不会扫描、推送或提交下载；清理到恢复线后，须在插件页面手动解除保护。旧下载继续，既有等候队列保留。

## 升级

停止 MoviePilot 后覆盖 `smartmoviepush` 文件夹，再重启容器即可。不要删除 MoviePilot 的配置数据库；插件密码、队列、历史记录和设置都存放在 MoviePilot 数据中。

## 常见问题

- 看不到插件：确认目录层级是 `plugins.v2/smartmoviepush/__init__.py`，然后重启 MoviePilot。
- 密码不知道：按首次打开页面提示联系 `@SDFSDFSF12321` 获取。
- 点击立即运行但未下载：检查同时下载上限、硬盘保护状态、站点是否可用以及 MoviePilot 过滤规则。
- 影片已下载但未标记入库：MoviePilot 整理完成不等于 Emby 已收录；必须在已启用的 Emby 媒体库中查到影片后，历史查询和日报才计为已入库。如云端尚未上传或 Emby 未刷新，标记会延后。已经发出的午夜消息是当时快照，后续查询原提交日期会显示新核验结果。
